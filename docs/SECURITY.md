# 安全设计与上线基线（v1.0.4）

## 1. 默认安全边界

- 交互终端和普通命令工具仅允许只读命令。
- 配置写入必须经过审批单、预先批准的回滚命令、变更前配置快照、设备验证和观察窗口。
- 配置/回滚命令只允许 SSH 驱动；传统 eNSP Telnet 只读。
- 高危命令由策略层拒绝；策略是纵深防御，不替代设备 AAA。
- 批量配置先对整个批次做本地预检，之后逐台执行；失败时逆序补偿，非跨设备原子事务。

## 2. RBAC 与双人审批

MCP 身份来自 MCP 子进程环境，而不是模型可传入的工具参数：

- `NETOPS_OPERATOR_ID`：1-128 字符身份 ID。
- `NETOPS_OPERATOR_ROLE`：`viewer` / `operator` / `approver` / `admin`。
- `NETOPS_REQUIRE_DUAL_APPROVAL`：`true` 时，申请人与审批人必须不同；apply 时再次校验已保存的 requester/approver。

角色边界：

- viewer：只读设备、终端、诊断和任务状态。
- operator：viewer + 设备登记、审批申请、已批准变更执行和批量编排。
- approver：viewer + 审批、变更确认、手动回滚和审计读取。
- admin：全部权限。

默认 `netops-all` Profile 会在同一 Harness 会话中同时启动 operator 与 approver 两个 MCP 子进程。这是便捷的逻辑角色分离，不是强制双人审批。生产环境若要求不同自然人审批，必须使用不同 Windows/Ubuntu OS 账户和独立 Harness 会话，或接入企业身份认证/外部审批系统；两个角色进程应访问同一数据库与密钥文件。

**重要限制：** 本项目的环境变量身份是应用层轻量 RBAC，不是企业 SSO/MFA。对能修改 Profile、进程环境、`.env`、可执行文件或 OS 账户的管理员，身份并非不可伪造。生产上线应接入企业身份提供方、MFA、受控跳板机、受审计的系统账户和独立审批系统。

## 3. 凭证与配置数据

- 设备密码、变更前配置快照、审批命令和回滚命令使用 Fernet 加密后写入 SQLite。
- 事务执行/验证/回滚回显在写入前经过常见敏感字段脱敏。
- 审计记录会递归脱敏敏感字段，并识别常见 Huawei/H3C/Cisco 口令、SNMP community、AAA key、PSK 和私钥材料。
- 可以使用 `${NETOPS_SECRET_NAME}` 作为命令密钥占位符；其值从 MCP 进程环境或项目 `.env` 解析，执行前才注入内存。新建变更事务会将该次执行实际解析出的回滚命令和密钥值再次用 Fernet 加密冻结在事务记录中，确保观察窗口期间环境变量轮换不会让回滚误用新值；明文只在当前 MCP 进程内存中使用。
- 脱敏基于已知语法的 best-effort 规则，不保证覆盖所有厂商/版本/自定义命令。生产命令中不要直接写明文密码、SNMP community、VPN PSK 或 API token。

### Fernet 密钥要求

`CREDENTIAL_ENCRYPTION_KEY` 是数据库加密根密钥：

1. 必须单独安全备份，限制为项目服务账户可读。
2. 数据库备份必须与该密钥版本一同管理。
3. 升级期间不应重新生成/更换该密钥。
4. 丢失密钥后无法恢复既有加密密码、快照和审批命令。
5. 密钥轮换需要单独的解密-重加密迁移程序，不要手动编辑 `.env` 完成所谓轮换。

## 4. 事务恢复和多进程

- 审批消费与创建 `applying` 事务使用同一个 SQLite 事务。
- `applying` 状态先落库再发送第一条配置命令。
- 多个 stdio MCP 子进程通过数据库旁边的 filelock 文件选举单一 rollback worker。
- 超过安全等待期仍处于 `rolling_back` 的事务标记 `rollback_failed`，不自动重复发送未知是否已成功的回滚命令。
- 中断的 `applying` 事务尝试执行预先批准的回滚；网络不可达时会留下失败状态，要求人工核查设备实际状态。

恢复策略仍无法消除设备断电、MCP 进程崩溃、网络分区发生在设备已执行而应答未到达等不确定窗口。必须保留设备 OOB 管理路径、带外控制台和人工恢复流程。

## 5. 管理面和网络隔离

- MCP 通过 Harness stdio 启动，不监听公网 HTTP 端口，不提供独立 Web Dashboard。
- Windows Harness 远程连接 Ubuntu 时使用 OpenSSH stdio 隧道；建议 SSH 公钥认证、严格验证 host key、限制系统账户和命令执行范围。
- 设备管理面应放在隔离管理 VLAN/VRF；防火墙只允许 MCP 主机到设备必要管理端口。
- eNSP Telnet 只能用于隔离实验网络，不应在生产网开放。
- 设备侧采用独立 AAA 账号、最小命令授权和命令审计；不要使用共享管理员账号。

## 6. 命令与模板安全

- 只读工具一次只接受一条 CLI 命令；拒绝换行、NUL 和分号命令分隔符。
- 写命令需要通过配置审批服务再次验证命令分类、归一化结果、设备连接类型和回滚命令。
- 模板只渲染计划，不会自动连接/改动设备；必须由工程师确认目标设备型号、已有配置、前置条件和回滚方案。
- 配置差异是脱敏文本 diff，不等同于变更归因或安全基线评估。
- 多设备批量变更是补偿式编排，不是分布式事务；批量回滚失败必须人工复核。

## 7. 生产上线检查

- 在同型号、同软件版本实验设备上验证配置命令和逆向回滚命令。
- 若启用强制双人审批，确保 requester/approver 使用不同 OS 身份、独立 Harness 会话和受控 Profile；不要把同一 `netops-all` 会话当作双人认证。
- 审核所有新增角色权限及配置模板；限制 admin 身份数量。
- 配置 AAA 最小权限、SSH 管理 ACL、OOB 管理和日志留存。
- 验证 Fernet 密钥备份/恢复和 SQLite 备份恢复。
- 对依赖进行漏洞扫描，固定发布依赖版本，定期更新。
- 在隔离环境模拟配置下发中断、回滚中断、设备离线、输出截断、数据库不可写和批量补偿失败。
- 完成 Harness 版本兼容性测试与真实设备回归后，方可考虑生产使用。
